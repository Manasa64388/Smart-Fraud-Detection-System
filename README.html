🛡️ Smart Fraud Detection System

Secure Banking Transaction Monitoring Platform

A DBMS-based web application developed using PHP, MySQL, HTML5, CSS3 and JavaScript that records banking transactions, detects suspicious activities and provides real-time fraud monitoring through an Admin Dashboard.

Explore Project

📖 Introduction

The rapid growth of digital banking and online payment systems has made financial transactions more convenient than ever before. However, this convenience has also increased the risk of fraudulent activities. Banks and financial institutions process thousands of transactions every day, making manual fraud detection difficult, time-consuming and inefficient.


The Smart Fraud Detection System is a web-based application designed to monitor banking transactions and automatically identify suspicious activities using predefined fraud detection rules. The system provides secure user authentication, transaction recording, fraud analysis, database management and administrative monitoring through an integrated dashboard.


This project demonstrates the practical implementation of Database Management System (DBMS) concepts including relational database design, primary keys, foreign keys, transactions, triggers, authentication and data security techniques.

❗ Problem Statement

Financial fraud is one of the major challenges faced by banking institutions. Traditional fraud detection approaches often depend on manual monitoring and investigation, which can delay the identification of suspicious transactions.


Fraudulent activities such as unusually large transactions or transactions from unexpected locations can result in significant financial losses if not detected quickly. Therefore, an automated system is required to monitor transactions in real time and flag potentially fraudulent activities for further investigation.

🔍 Existing System

Traditional banking systems often rely on manual monitoring and verification of transactions. Fraud detection usually occurs after the transaction has already been processed, which increases the risk of financial loss.


Limitations of Existing System


  • Manual verification process.
  • Time-consuming transaction monitoring.
  • Delayed fraud detection.
  • High dependence on human intervention.
  • Possibility of overlooking suspicious activities.
  • Limited real-time monitoring capabilities.

🚀 Proposed System

The Smart Fraud Detection System introduces an automated approach for monitoring transactions and identifying suspicious activities. The system records customer transactions, applies fraud detection rules, stores transaction data in a MySQL database and provides real-time monitoring through an administrative dashboard.


Advantages of Proposed System


  • Automated fraud detection.
  • Real-time transaction monitoring.
  • Secure user authentication.
  • Transaction history maintenance.
  • Administrative analytics dashboard.
  • Reduced human intervention.
  • Improved fraud visibility.

📦 Module Description

🏠 Home Module

The Home Module acts as the landing page of the system. It provides navigation links for Customer Portal, Admin Portal, Login and Registration.

📝 Registration Module

Allows new customers to create accounts by providing their name, account number and password. Passwords are securely stored using hashing techniques.

🔐 Login Module

Authenticates users and administrators. After successful authentication, the system creates a session and redirects users to the appropriate page.

💳 Transaction Module

Accepts transaction details such as transaction amount and current location from customers. Each transaction is evaluated before being stored.

Applies fraud detection rules to determine whether a transaction is suspicious. Transactions are marked as either Safe or Fraudulent.

Provides transaction analytics, fraud reports, customer details and monitoring information for administrators.

🚩 Fraud Detection Rules

The Smart Fraud Detection System uses a rule-based approach for detecting suspicious activities. Each transaction is evaluated against predefined rules.


Rule No. Fraud Rule Description
1 High Amount Detection Transactions greater than ₹20,000 are automatically flagged as suspicious.
2 Location Mismatch Detection If the current transaction location differs from the user's previous location, the transaction is marked as suspicious.

🗄️ Database Design

The system uses MySQL as the backend database. The database consists of two main tables: Users and Transactions.


Users Table

Field Type Description
id INT Primary Key
name VARCHAR Customer Name
account_no VARCHAR Unique Account Number

Transactions Table

Field Type Description
id INT Primary Key

⚙️ Database Trigger

The project implements a database trigger to automatically update the user's last transaction location whenever a new transaction is inserted.


<

Trigger Implementation

CREATE TRIGGER update_location_after_transaction
AFTER INSERT ON transactions
FOR EACH ROW
BEGIN
    UPDATE users
    SET last_location = NEW.location
    WHERE id = NEW.user_id;
END;

This trigger automatically updates the user's last known location whenever a new transaction is inserted into the transactions table.


Using triggers improves automation and ensures database consistency without requiring additional application logic.
